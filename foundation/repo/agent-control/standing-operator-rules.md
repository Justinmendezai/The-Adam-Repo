# Standing operator rules

Non-negotiable defaults for Adam factory runs. Copy into the target repo via `setup-adam` / `adam-foundation-sync`. Replace “operator” with the human who owns the product.

- Push feature branches to origin before done; never leave WIP local-only.
- Gate `origin/main` with an independent audit (third-party critic + Bugbot or equivalent); escalate only for architecture impact.
- After intake grill: dual research pods (positive + anti) before plan ADRs.
- No mid-run operator gates for taste; taste / live review only at the end via `human-queue`.
- Run all CLI yourself; monitor background jobs — no silent stalls.
- Anti-theater: real producer/consumer for PASS; no greenwashed scorecards.
- Rework ledger on every block/retry; recurring class → skill or HANDOFF patch.
- UI slices: follow the project's frontend taste + theme packet when those skills are present.
- Do not invent product intent. If a gap would change what gets built, ask.
